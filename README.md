# aram-augment-advisor

《英雄联盟》海克斯大乱斗的符文选择助手：**截屏认出屏幕上的三个符文 → 查本地胜率库 → 直接告诉你选哪个。**

`Python` `OpenCV` `OCR` `Riot Live Client API` `MIT`

![演示](docs/demo-cards.png)

---

## 它做什么

打游戏时开着，一出现海克斯选择界面就自动识别并打印建议：

```
[21:32:41] 发现海克斯界面 -> shot_002.png
    卡片 #1 ✓  万用瞄准镜       (OCR 精确命中词表)
    卡片 #2 ✓  大力            (OCR 精确命中词表)
    卡片 #3 ✓  由暴生急         (OCR 精确命中词表)

[推荐] 疾风剑豪 · 3 级   （他本赛季平均胜率 57.5%）
  1. 大力          胜率 57.7%   比平均 +0.2%   （符文全局 51.1%）
  2. 由暴生急       胜率 51.6%   比平均 -5.9%   （符文全局 46.9%）
  3. 万用瞄准镜      胜率 50.9%   比平均 -6.6%   （符文全局 48.3%）
```

**注意第一行**：「大力」胜率 57.7% 看起来最高，但疾风剑豪本赛季的平均胜率就有 57.5% —— 这个符文对他几乎没用。而另外两个低于他平均 6 个百分点，是会拖后腿的。

只报胜率会误导人。**报"比这个英雄的平均高多少"才有意义。**

支持**刷新**：符文刷新后会自动重新识别、给出新的建议，而不是继续显示旧的。

## 怎么工作

### 识别链路：六道关

```
截图
 ├─ 1. 找卡片      轮廓检测，每帧现找，不依赖分辨率
 ├─ 2. 内容检查    卡面必须是深色底（挡掉英雄选择界面的彩色原画）
 ├─ 3. 对局门禁    本地数据接口连得上 = 在对局中（挡掉大厅、英雄选择）
 ├─ 4. 关键词挡板  卡面出现「锻造器」→ 属性锻造器界面，不是符文
 ├─ 5. OCR 定名    整张卡片喂 OCR，排除技能角标后取字号最大的行
 └─ 6. 置信度门槛  三张里至少两张命中词表，否则整帧丢弃
```

**六道关的取舍原则：宁可什么都不输出，也不要输出一个看起来很像答案的错误答案。**

这条原则是踩坑换来的。属性锻造器界面曾经顺利通过前三关，OCR 读出的三个猜测全被自己标了「低置信度」，但程序还是把三个错误答案连同胜率表一起打印了出来 —— 我看到的是三个真实符文名加一份推荐，**完全不像出错的样子**。

### 数据链路

```
aramkit.com ──爬虫──> raw/*.json ──建库──> SQLite ──查询──> 建议
                                            ↑
Riot 本地接口 ──── 英雄名 + 等级 ────────────┘
```

- **符文胜率**来自 [aramkit.com](https://aramkit.com)（静态 JSON，无需解析 HTML）
- **英雄和等级**来自 Riot 官方本地数据接口 `127.0.0.1:2999`，不做头像识别
- **不自动点击、不注入游戏进程**，只读屏幕

## 安装

需要 **Windows**（用到 `pywin32` 读窗口位置）和 **Python 3.10+**。

```bash
pip install -r requirements.txt
```

## 使用

### 第一次：准备数据

```bash
python crawler.py          # 抓符文/英雄胜率，约 5 分钟，99 MB
python build_db.py         # 整理成 SQLite
```

`python download_icons.py`（抓 216 个符文图标）是**可选的，不跑也能用** ——
图标只被「图标匹配」用到，而那个功能实测准确率 20.4%，已经默认关闭。

### 之后：开用

```bash
python watch.py
```

打游戏时开着它。出现海克斯选择界面就会自动识别并打印建议。

### 自测

```bash
python selftest.py
```

```
正样本   10/10 张整图全对
卡片     30/30 张正确
负样本   3/3 正确拒绝
```

测试样本在 `tests/fixtures/`，是从真实游戏截图裁出来的（已涂黑含召唤师 ID 的区域）。
改完识别逻辑跑一下，就知道有没有改坏 —— 这个测试**抓到过一次真实的回归**：
想把技能角标的处理改得更通用，结果把原本正确的「升级：耀光」改成了「伤害」。

样本可以用 `python tests/make_fixtures.py` 从自己的 `shots/` 重新生成。

### 组合加成（可选）

海克斯的强度不只是单个符文，还看**和已经选过的符文搭不搭**。
数据库里存了 1,730 条「两个符文一起选」的胜率数据，配上已选符文就能用上。

问题是：**游戏画面上不显示已选的符文，Riot 的本地接口也不暴露**（只有英雄、等级、装备）。
截图里卡片下方那排小图标是装备和锻造器，不是符文——放大确认过。

所以只能手动告诉它。在项目目录建一个 `picked.txt`，每选一个符文就往里加一个 id：

```
2100, 1058
```

然后推荐就会变成：

```
  1. 秘术冲拳   胜率 58.4%   比平均 +5.3%   （符文全局 50.9%）
       ⚑ 和已选的「急速之追求」是热门组合：组合胜率 70.2%（样本 31,152）
```

**注意**：源数据每个英雄只收录前 10 对组合，所以查不到不代表搭不上，
只代表"不在该英雄最热门的 10 对里"。

---

### 赛后复盘（大模型）

`watch.py` 是**选之前**给建议，`review.py` 是**打完一局之后**做复盘：

```bash
python review.py masteryi 1058,1047,2034
```

```
【复盘】无极剑圣 · 本赛季平均胜率 53.2%
  最好的一选：秘术冲拳 (+5.3%)
  最亏的一选：鲨鱼暴风 (-4.5%)
  平均收益：+0.9%

开局秘术冲拳拿得挺对，剑圣前四的符文，稳。关键暴击能用但一般，没啥惊喜。
鲨鱼暴风这个选亏了，样本小还不涨胜率，纯陷阱，下次看见直接跳过。
以后先抢掷骰狂人或终极九头蛇那档，第三手别凑冷门，照大数据走就完事了。
```

**设计上最要紧的一条：不让大模型做算术。**

胜率、收益率、样本量全部由 Python 从数据库查好再喂进去，模型只负责把数字翻译成人话。

LLM 算 `55.3 - 53.2` 可能给你 1.1 也可能给你 3.2，而且你很难发现；但让它组织语言、下判断，它很擅长。

**分工是：程序负责事实，模型负责表达。**

这是所有 LLM 应用的通用原则——数字、时间、排序、统计，一律程序算完再交给模型。

配置（key 不要写进代码）：

```bash
setx MIMO_API_KEY "sk-你的key"      # 设完要重开终端
```

用的是[小米 MiMo 开放平台](https://mimo.mi.com)，兼容 OpenAI 接口。
换 `base_url` 和 `model` 就能切到 DeepSeek / 通义 / GLM。

### 语义检索（RAG）

`rag.py` —— 用自然语言查符文，不用记名字：

```bash
python rag.py "能回血的符文"
```

```
查询改写：能回血的符文  →  生命偷取 全能吸血 治疗 回复

--- 检索到的 5 条（RAG 的 R）---
  1. [0.6703] 渴血          获得15%全能吸血
  2. [0.6531] 术士果汁盒      获得(10%+3.5%)全能吸血
  ...

--- 模型基于以上资料的回答（RAG 的 G）---
提供全能吸血的符文有：渴血、术士果汁盒、最终形态……
```

**三步：检索 → 增强 → 生成**

1. **检索**：216 个符文的描述用中文语义模型编码成向量，问题也编码成向量，算余弦相似度取 Top-5
2. **增强**：把 Top-5 的描述拼进提示词
3. **生成**：模型只根据这些资料回答（提示词里明确要求「资料里没有的不要编」）

**两个实测出来的优化（都有数据支撑）：**

| 方案 | 5 个查询的命中率 |
|---|---|
| TF-IDF（字面匹配） | 「攻速」搜不到「攻击速度」，基本失效 |
| 语义向量 | 20/25 |
| **语义向量 + 查询改写** | **24/25** |

**查询改写是关键一步**：玩家说「回血」，描述里写的是「生命偷取」——词对不上，向量再强也对不齐。先用模型把口语问题翻译成游戏术语，再去检索。

代价是检索一次要调两次 API（一次改写、一次生成），所以留了 `--no-rewrite` 开关。

国内下载模型要先设镜像：

```bash
set HF_ENDPOINT=https://hf-mirror.com
```

## 项目结构

```
watch.py              主循环：截图 → 识别 → 查库 → 打印建议（成品就是它）
recognize.py          识别：找卡片 + OCR + 词表匹配
advise.py             推荐：查库、排序、组合加成
liveapi.py            Riot 官方本地接口，拿英雄名和等级
wincap.py             Windows 截图/窗口的公共部分（watch 和 capture 共用）

review.py             赛后复盘：把选择交给大模型生成分析
rag.py                语义检索：用自然语言查符文（RAG）

crawler.py            爬虫：aramkit → raw/*.json
build_db.py           建库：raw/*.json → SQLite
download_icons.py     下载符文图标（可选，图标匹配已停用）

selftest.py           跑测试样本，报告识别准确率
tests/make_fixtures.py 从游戏截图生成测试样本（涂掉含召唤师 ID 的区域）

capture.py            手动截一张游戏画面（调试用）
calibrate.py          标定卡片位置（换分辨率时用）

dev/                  探索过程的中间脚本，不参与运行
```

## 数据来源与合规

**数据来源**：[aramkit.com](https://aramkit.com)（robots.txt 允许抓取）。仅供个人学习，**请勿重新分发数据**。仓库里不含任何抓取结果。

**合规边界**：

- ✅ 只读屏幕，不注入游戏进程，不模拟点击
- ✅ 英雄信息走 Riot 官方提供的本地接口
- ⚠️ 实时给出建议处于 Riot 第三方软件政策的灰色地带。**请自行判断风险**
- ❌ 不要改造成自动选择符文 —— 那属于自动化，明确违规

游戏截图和召唤师 ID 都不在仓库里（见 `.gitignore`）。

## 已知不足

- **图标匹配不可用**。原本想用它做第二道交叉验证，量了一下发现**准确率只有 20.4%**
  （93 张卡片，第一名才对 19 张）。即使只看分数 ≥0.8 的那批也只有 71%。
  根本原因见下面「踩过的坑」⑨。所以它不参与任何判定。
- **无法自动获取已选的符文**（组合加成只能手动喂 `picked.txt`）。游戏界面上不显示，
  Riot 本地接口也不暴露。
- **`detect_cards` 用亮度阈值**，遇到明亮背景（比如粉红森林那张地图）会框歪。目前不影响结果（OCR 不依赖框的精度），但有残留风险。
- **样本量不大**：实际攒了 31 张截图 / 93 张卡片（全部人工核对过），
  但仓库里只放了 10 张（30 张卡片）作为测试样本 —— 原尺寸 PNG 一张 700 KB，
  全放进来要 20 MB。取舍和实测数据见 `tests/make_fixtures.py` 的注释。
- **只有中文客户端**验证过。

## 踩过的坑

这个项目最有价值的部分大概是下面这些 —— 没有一个是预先设计出来的，全是跑起来才暴露的。

**① 坐标写死 = 绑定分辨率。**
一开始把三张卡片的位置写成 1920×1080 下的绝对像素。后来我的游戏窗口变成 2000×1125，坐标全部失效。改成每帧用轮廓检测现找。

**② 窗口最小化时会拿到 `0x0 @ (-32000,-32000)`。**
Windows 给最小化窗口的固定坐标。直接拿去截图会抛异常。

**③ 假阳性比报错危险得多。**
英雄选择界面中间也有三张并排的卡片，几何特征一模一样。程序识别出三个"符文"，打了三个绿勾，而那时候屏幕上根本没有海克斯。

**④ 一次错误可以六步全静默。**
明亮背景 → 亮度阈值把背景框进来 → 闭运算把卡片和按钮连成一块 → 框高从 528 变 603 → 名称区下移到类别标签上 → OCR 只读到「伤害」→ 和词表里所有名字相似度都是 0.000 → 并列时按字典序随便挑了一个。**输出了一个带绿勾的错误答案。**

**⑤ 「低置信度」也要拒绝，不能只给警告。**
猜测错了就说"我不知道"，不能说"我觉得是 X（但可能不对）"。

**⑥ 收益率要减英雄自己的基线，不是符文的全局胜率。**
减错的后果：皮城执法官自身胜率只有 46.7%，他和任何符文的组合都低于符文全局平均，于是"三个收益全是负数"天天误报。

**⑦ 用时间做冷却，会挡掉刷新。**
「20 秒内不重复输出」在符文刷新后会把新选项挡在门外 —— 而刷新恰恰是最需要看建议的时刻。改成按「选项组合变了没有」判断。

**⑧ 形态明确的东西，别用模糊阈值去猜。**
技能角标 `[Q]` 和符文名的字号完全一样。「差 10% 以内算并列」这种模糊规则会把类别标签也放进来。按形态排除（括号里一个 QWER 字母）才对。

**⑨ 量完发现不行，就别加 —— 删掉它比硬塞进去有价值。**
216 个符文里**有 24 组共用同一个图标**（同一系列、升级版、「所选英雄技能」类各有一个通用图标），所以纯图标匹配原理上就不可能唯一识别。这个早就知道，但当时的结论是「卡片框检测不准导致的，框修好了图标就能用」——**那是猜的**。

后来卡片框在 93 张样本上验证过了，回头量图标匹配的真实水平：

```
图标第一名就对:  19/93 = 20.4%

按分数分档：
  0.0~0.4   0/41     0.0%
  0.4~0.6   0/22     0.0%
  0.6~0.8   9/16    56.2%
  0.8~1.0  10/14    71.4%
```

**最高分档也只有 71%。** 接进决策链等于往一个 93/93 正确的系统里塞一个 80% 错误的信号。

原本的计划是「加第二道信号做交叉验证」，量完之后正确的做法变成了**把这段死代码删掉**——
它每帧白跑 648 次模板匹配，输出的还是误导性信息。

**「加一个信号会更稳」是个很自然的直觉，但它是个假设，得量。** 量完不成立，就要有把它删掉的决心。
